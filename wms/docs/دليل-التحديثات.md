# دليل تحديثات Y-ai WMS

هذا الملف يلخّص آلية التحديث الآمنة المعتمدة في المشروع.

## الفكرة باختصار

- أنت تعدّل البرنامج محلياً.
- تبني **Installer جديد** (`Y-ai-WMS-Setup.exe`).
- ترفع على **GitHub**:
  1. ملف `version.json` في **جذر المستودع**
  2. ملف التثبيت داخل **GitHub Releases** (وليس كمجلد `releases` في الكود)
- عند العميل: البرنامج يقرأ `version.json` ويقارن الإصدار.
- إذا وُجد إصدار أحدث → يظهر زر **تحديث** بجانب تبديل الأرقام في أعلى الشاشة.

## مستودع GitHub الخاص بك

| البند | القيمة |
|--------|--------|
| المستودع | https://github.com/GavanBadea/Y-ai |
| ملف التحديث | `version.json` في جذر فرع `main` |
| رابط القراءة (Raw) | https://raw.githubusercontent.com/GavanBadea/Y-ai/main/version.json |
| ملف التثبيت | داخل **Releases** وليس داخل شجرة الملفات |

> **مهم:** لا تنشئ مجلداً باسم `releases` داخل المستودع.  
> مسار `/releases/download/...` يُنشأ تلقائياً من GitHub عند نشر **Release**.

## شكل ملف `version.json` على GitHub

انسخ من الملف: `docs/version-github-template.json`

مثال جاهز:

```json
{
  "version": "2.2.1",
  "releaseDate": "2026-07-02",
  "notes": [
    "إصلاحات في قسم المحاسبة",
    "تحسينات في واجهة فاتورة المبيعات"
  ],
  "installerUrl": "https://github.com/GavanBadea/Y-ai/releases/download/v2.2.1/Y-ai-WMS-Setup.exe",
  "mandatory": false
}
```

| الحقل | المعنى |
|--------|--------|
| `version` | رقم الإصدار الجديد (يجب أن يكون أعلى من المثبّت عند العميل) |
| `releaseDate` | تاريخ النشر |
| `notes` | ملاحظات تظهر للمستخدم |
| `installerUrl` | رابط تنزيل ملف `.exe` من Release |
| `mandatory` | `false` = اختياري، `true` = تحديث مهم |

## خطواتك عند كل إصدار جديد

### 1) عندك (التطوير)

1. عدّل المشروع في `wms`.
2. حدّث `wms/version.json` ليطابق إصدار المثبّت الجديد (مثلاً `2.2.1`).
3. شغّل `build-installer.bat` من مجلد `Y-ai-package`.
4. خذ ملف `Y-ai-WMS-Setup.exe` من مجلد `output`.

### 2) على GitHub

#### أ) نشر ملف التثبيت (Release)

1. افتح: https://github.com/GavanBadea/Y-ai
2. من الشريط الجانبي: **Releases** → **Create a new release**
3. **Tag:** `v2.2.1` (مثال)
4. **Title:** `Y-ai WMS v2.2.1`
5. ارفع الملف: `Y-ai-WMS-Setup.exe`
6. اضغط **Publish release**
7. انسخ رابط التحميل، سيكون مثل:
   ```
   https://github.com/GavanBadea/Y-ai/releases/download/v2.2.1/Y-ai-WMS-Setup.exe
   ```

#### ب) تحديث `version.json`

1. افتح ملف `version.json` في جذر المستودع (أو أنشئه).
2. ضع رقم الإصدار الجديد و`installerUrl` من الخطوة السابقة.
3. احفظ (Commit).

### 3) عند العميل

1. يفتح البرنامج (يجب اتصال إنترنت).
2. يفحص تلقائياً: `version.json` على GitHub.
3. إذا `version` على GitHub **أعلى** من `wms/version.json` المثبّت:
   - يظهر زر **تحديث** بجانب تبديل الأرقام.
4. المستخدم يضغط **تنزيل التحديث** ويثبّت الـ Installer الجديد.

## ما الذي يقرأه البرنامج داخلياً؟

| الملف / الإعداد | الدور |
|-----------------|--------|
| `wms/version.json` | الإصدار **المثبّت حالياً** عند العميل |
| `UPDATE_MANIFEST_URL` في `.env` | رابط ملف GitHub الخارجي |
| `GET /api/system/update-meta` | يعيد الإصدار المحلي + رابط الملف الخارجي |
| الواجهة (`AppLayout`) | تقرأ الملف الخارجي وتقارن الإصدارات |

الإعداد الافتراضي في `.env`:

```env
UPDATE_MANIFEST_URL=https://raw.githubusercontent.com/GavanBadea/Y-ai/main/version.json
```

## اختبار سريع

1. اترك عند العميل `version.json` المحلي = `2.2.0`
2. على GitHub ضع `version.json` = `2.2.1` مع `installerUrl` صحيح
3. أعد تشغيل الخادم وحدّث الصفحة
4. يجب أن يظهر زر **تحديث**

إذا لم يظهر:

- تأكد أن ملف GitHub **ليس فارغاً** ويحتوي JSON صحيح
- تأكد أن رقم الإصدار على GitHub **أعلى** من المحلي
- تأكد أن المستودع **Public**
- تأكد من الإنترنت على جهاز العميل

---

## ملاحظات أمان

- لا ترفع `backend.zip` و`frontend.zip` للاستبدال التلقائي داخل الجهاز (معقّد وغير آمن).
- الطريقة المعتمدة: **Installer كامل** لكل إصدار.
- البرنامج **لا يثبّت التحديث تلقائياً** — فقط يُنبّه ويفتح رابط التنزيل.
